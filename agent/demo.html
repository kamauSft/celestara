Built on the real products from codzure-solutions.vercel.app — NeoBuk (SME workspace) and Ask Nyumbani / Nyumba Zetu (land & homes). The model is a router. Tools, confirmation, grounding, and evals are the product.

What 1% agents do

  • Call tools on this shop / these listings
  • Multi-step: parse → tool → result → next tool
  • Writes return a draft. Never silent save
  • Refuse cash-in-car-park and invented balances
  • Golden tasks fail the build if they regress
  • Still works if the API key is missing

99% “AI feature”

A chat box that restates the marketing site. Invents listings and balances. Writes with no draft — or cannot write at all. Dies without an API key. No evals. Two separate bots for two apps. Sounds like a lawyer on land titles.

1% agentic product

One brain, two toolkits. Intent becomes a port call. Reads run now. Money and listings wait for Confirm. Diligence is bound to a listing id and disclaims legal advice. Frozen utterances in CI. WhatsApp is a channel later — not a substitute for P0 reliability.

1

Utterance

Plain language, including Sheng mix. “sold 3 bags to Mary 1500” / “3-bed Ruaka under 8M near a school.”

2

Route

getTools("neo" | "nyumba") only. Knowledge (who built this) is static — never scraped at runtime.

3

Tool call

JSON to a port: RecordSale, SearchListings, DueDiligence, Alerts. Logged: name, input, userId, time.

4

Ground

Result from stub (today) or live backend (merge). Empty set → “I don’t have that.” Never hallucinate a row.

5

Read now

Search, performance, outstanding, checklist. User sees real cards immediately.

6

Draft write

requiresConfirmation + draftId + summary. UI Confirm / Discard. No second parse to save.

7

Eval

~20 golden tasks per product. If Mary’s sale or Ruaka search breaks, we do not ship.
