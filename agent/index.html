A top 0.5% agentic layer is an operator, not a chat widget.

This business case is the plan for what to build, what to refuse, and how we will know we are in the top fraction. It is written so a founder and a teammate can split work without inventing a second AI project.

1. Verdict

We do not win by wrapping Claude in a text box. That is what 99.5% of product AI looks like in 2026. We win if the agent finishes a job the user already pays for with time, cash, or fear — then waits for a yes before anything important is saved.

Neo must do this

“Sold 3 bags cement to Mary, 1,500” becomes a structured draft. “Who owes me?” is answered from this shop’s books.

If we miss this, we are a chatbot that talks about bookkeeping.

Nyumba Zetu must do this

“3-bed Ruaka under 8M near a school” returns real listings. Title fear gets a walkthrough on that listing, not a blog post.

If we miss this, we are another listings site with an FAQ bot.

One engine, two toolkits. Same reasoning core, same confirm-before-write rule, same eval harness. Only the actions and the product facts change. Recommended stance: make two flagship jobs boringly reliable on stub data, then swap adapters — do not expand the tool surface to look busy.

2. What top 0.5% actually means

Not model brand. Not token volume. A product standard:

  1. Job completion, not conversation. Value = a confirmed action or a grounded answer from live data.
  2. The model is a router, not the product. Tools, contracts, and confirmation are the product. The LLM is replaceable.
  3. Write gates are sacred. Money, inventory, listings, records → draft. Reads run now. No silent writes.
  4. Grounded in the user’s world. Neo uses this shop. Nyumba searches these listings. Knowledge (what the product is) stays separate from tools (what it can do).
  5. Eval before vibe. Frozen golden tasks on every change. If sale-parse or Ruaka-search regresses, we do not ship.
  6. Works where the user already is. Phone-first. Later WhatsApp. English and Sheng/Swahili in one utterance.
  7. Honest about limits. Diligence is a checklist, not a legal opinion and not ArdhiSasa. Top products earn trust by declining.

We are average if we ship this

A floating “Ask AI” that restates the marketing site. Unbounded writes. Hallucinated listings or balances. One giant prompt and no ports (merge becomes a rewrite). No logs. Due diligence that sounds like a lawyer. A demo that dies without an API key.

3. Why this problem

Neo’s buyer currently keeps the business in their head, a notebook, or WhatsApp. They do not want software. They want the afternoon back, and they want to stop leaking money — unpaid credit, dead stock, mystery margins. The agent must operate sales, expenses, inventory, and workflows — not describe them.

Nyumba’s buyer is trying not to get scammed on land in Nairobi, Kiambu, Ruaka, Syokimau, Karen, Westlands. Classifieds and portals barely offer title guidance. Search gets them in; due diligence is why they stay; seller drafts grow supply.

Studio advantage: one Nairobi studio, two products, parallel development. A shared brain is cheaper than two AI projects. Isolation (/agent, AGENT_ env, stub adapters) is how we stay fast and merge-safe.

5. Principles we will not negotiate

  • Purely additive. Everything in /agent. Host merge is one registerAgent call plus adapter swap.
  • Ports, not hard-wiring. Brain asks for RecordSalePort / SearchListingsPort. Stubs today, real functions later.
  • Confirm before write. Read immediately. That is the trust product.
  • Knowledge ≠ tools. Codzure/Neo/Nyumba facts are static and offline. Tools are actions.
  • Local usefulness without a key. A deterministic operations brain (parse → same tools → same drafts) is the floor. Claude is the upgrade.
  • Decline well. Skip title search, pay cash, invent a balance → refuse and say why.

Architecture, in one picture:

User (app · later WhatsApp) → handleAgentMessage → loop (LLM tools or local operations brain) → getTools("neo" | "nyumba") → ports in contract.ts → stub adapters now / real adapters at merge → host backends we never edit

7. Design these two journeys, not “a chat UI”

Neo — 20 seconds vs a notebook

  1. Owner: “sold 3 bags cement to Mary 1500.”
  2. Draft card: Mary · 3 × cement · KES 1,500 · paid/unpaid.
  3. Confirm. Ledger updates.
  4. “Who has outstanding balances?” → named, aged debt.
  5. Alert: cement at 4, reorder 12 — still a draft restock note.

Nyumba — search, then safety

  1. “3-bedroom in Ruaka under 8M near a school.”
  2. 1–3 real listings with price, title status, nearby.
  3. “Walk me through the cheap plot.”
  4. Checklist on that listing. Unverified/disputed = high risk. Never cash in a car park.
  5. Seller: draft + comps → confirm.

If a reviewer has three minutes, they see Neo journey steps 1–3 and Nyumba steps 3–4. That is the competitive demo.

8. How 0.5% teams actually operate

Freeze golden tasks now

Neo: sale parse (EN + Sheng), week performance, who owes me, alerts, confirm, “who built this.”

Nyumba: Ruaka 3-bed under 8M, Kiambu land, “is this plot safe,” documents to demand, comps, source URL.

Pass: right KES, right area, no fake listing ids, write tools never commit in the parse turn.

Trust is a feature

Diligence: guide, not advocate. Fixed disclaimer. No “pay the seller’s cousin.” Title status is data, not a verdict. Drafts are auditable (id, payload, user, time). Degraded mode still completes the flagship job with no API key.

Economics: do not spend on fine-tuning, multi-agent theatre, or a custom framework. Anthropic tool use plus a short loop is enough. Prove a shop records a real sale and a buyer finishes a listing-bound checklist. Monetisation follows trust. One brain × two products × (app + later WhatsApp) is the studio-level reason this exists.

11. Approve this — or ship a better form instead

  • We are building an operator, not a mascot.
  • Two flagship tools + confirmation + evals before WhatsApp or extra tools.
  • Due diligence is the Nyumba differentiator — guidance with a clear disclaimer, never a title guarantee.
  • One contract file is the meeting point with the other developer.
  • Any tool that writes without a draft is killed.
  • We will not start a second agent stack for the second product.

If that is not the plan, do not spend a model budget. A cleaner sale form and better listing filters will outperform a vague chatbot.

Immediate sequence

  1. Lock contract.ts with the host developer (Sale, Listing, request/response, ports).
  2. Freeze 20+20 golden utterances, including Sheng mix and “who built this.”
  3. Write the two flagship tools on Kenyan stub data.
  4. Confirmation protocol used by both products.
  5. Standalone runner + one-line INTEGRATION.md. Put it in a real owner’s and a real buyer’s hands. Listen for “useful,” not “cool.”
  6. Only then: listing-bound diligence, Neo alerts, seller comps, WhatsApp as a channel adapter.

That sequence is the competitive, reasonable solution. Everything else is theatre.
